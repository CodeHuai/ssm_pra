# 家具图片上传 实现指南（SSM + Servlet 3.0）

> 记录 `img_path` 图片上传功能的后端实现步骤与企业级做法。
> 前端已联调完成（弹框上传 + 表格缩略图），后端按本文档实现即可对接。

---

## 0. 核心认知（先看这节）

### 0.1 `img_path` 存的是 URL，不是图片
数据库存"结构化、要查询"的数据；图片是大块二进制，进库会拖垮性能、撑大备份。
**结论**：图片放文件系统/对象存储，`img_path` 只存一个指向它的 URL 字符串。

### 0.2 流程是"先上传、再存数据"两步分离
```
① 上传图片：前端 POST 文件 → 后端存盘 → 返回 URL
② 保存家具：前端把 URL 塞进 imgPath → 调 addFurn/modifyFurn → URL 进库
③ 展示图片：列表/查看拿到 URL → <img :src> 显示
```
**为什么分两步**：解耦（上传慢、保存快，互不拖累）、复用（一个上传接口多场景用）、失败隔离。

### 0.3 三个目录不要搞混
| 目录 | 谁用 | 谁管 | 配不配 |
|---|---|---|---|
| Tomcat 临时暂存目录（web.xml 的 `<location>`，**已省略**） | Tomcat 上传过程中暂存 | Tomcat 自动（work 目录） | 不配 |
| **最终保存目录**（`upload.dir = D:/upload/`） | Controller 把图永久写到这里 | **你** | 配，外部化 |
| 静态资源映射 `/upload/**` | 让浏览器能访问最终保存目录里的图 | Spring | 配 |

## 1. 配置（已完成 ✅）

### 1.1 `web.xml` —— Tomcat 层（multipart 硬限制）
在 `<servlet>`（dispatcherServlet）里、`<load-on-startup>` 之后加 `<multipart-config>`：
- `max-file-size` 5MB：单文件硬上限，超了 Tomcat 直接拒。
- `max-request-size` 10MB：整个请求上限（多文件兜底）。
- `file-size-threshold` 1MB：内存/磁盘分界。
- **故意省略 `<location>`**：它是临时暂存目录，让 Tomcat 用自带 work 目录即可，免写死。
- ⚠️ web.xml 由 Tomcat 在 Spring 之前解析，**不能用 `${}` 占位符**，只能写死字面值。

### 1.2 `springmvc.xml` —— Spring 层
```xml
<!-- ① multipart 解析器：把 Tomcat 解析好的转成 MultipartFile。id 必须正好叫 multipartResolver -->
<bean id="multipartResolver"
      class="org.springframework.web.multipart.support.StandardServletMultipartResolver"/>

<!-- ② 加载上传配置（谁要用 ${upload.dir} 就在谁那里加载） -->
<context:property-placeholder location="classpath:upload.properties"/>

<!-- ③ 静态资源映射：让 /upload/xxx.jpg 能访问到磁盘 ${upload.dir} 里的图 -->
<mvc:resources mapping="/upload/**" location="file:${upload.dir}"/>
```
> IDEA 对 `file:${upload.dir}` 报 "Cannot resolve location" 是**误报**（静态检查不跑占位符替换），运行时正常。

### 1.3 `src/main/resources/upload.properties` —— 外部化配置
```properties
upload.dir=D:/upload/                                   # 结尾带斜杠
upload.url-prefix=http://localhost:9991/upload/         # Controller 拼 URL 用
```
> 上 Linux 生产改成 `/data/upload/`，只动这个文件不改代码。

## 2. 上传接口 `UploadFileController`（待实现 ⏭️）

### 2.1 类与方法签名
```java
@RestController
@RequestMapping("/api/file")   // ⚠️ 必须是 /api/file，不是 /upload（见第 6 节常见坑）
public class UploadFileController {

    @Value("${upload.dir}")       private String uploadDir;   // D:/upload/
    @Value("${upload.url-prefix}") private String urlPrefix;  // http://localhost:9991/upload/

    @PostMapping("/upload")       // → POST /api/file/upload
    public Msg upload(@RequestParam("file") MultipartFile file) { ... }
}
```

### 2.2 逻辑（7 步，每步都有"为什么"）
| 步 | 做什么 | 为什么 |
|---|---|---|
| ① | `file.isEmpty()` 判空 | 没选文件就提交 |
| ② | 校验 `file.getSize()` 上限 | web.xml 是硬底线；这里做是为了返回**友好提示** |
| ③ | 取扩展名 + 白名单校验 | 从 `getOriginalFilename()` 截 `.xxx`，判断在 `.jpg/.png/...` 里 |
| ④ | 新文件名 = `UUID + 扩展名` | 防重名覆盖、防中文乱码、**防路径穿越**（绝不用原文件名存盘） |
| ⑤ | 目录不存在则建 | `dest.getParentFile().mkdirs()` |
| ⑥ | `file.transferTo(dest)` 落盘 | 真正写到 `D:/upload/` |
| ⑦ | 返回 `urlPrefix + newName` | 前端存进 img_path、显示图 |

### 2.3 `MultipartFile` 常用 API
| 方法 | 返回 | 用途 |
|---|---|---|
| `isEmpty()` | boolean | 有没有真传文件 |
| `getOriginalFilename()` | String | 原文件名（含扩展名） |
| `getContentType()` | String | 声明的 MIME（如 `image/jpeg`） |
| `getSize()` | long | 字节数 |
| `transferTo(File)` | void | 落盘 |

### 2.4 参考实现
```java
package com.huai.ssm.controller;

import com.huai.ssm.bean.Msg;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.multipart.MultipartFile;

import java.io.File;
import java.io.IOException;
import java.util.Arrays;
import java.util.List;
import java.util.UUID;

@RestController
@RequestMapping("/api/file")
public class UploadFileController {

    private static final List<String> ALLOWED_EXT =
            Arrays.asList(".jpg", ".jpeg", ".png", ".gif", ".webp");
    private static final long MAX_SIZE = 5L * 1024 * 1024; // 5MB

    @Value("${upload.dir}")
    private String uploadDir;

    @Value("${upload.url-prefix}")
    private String urlPrefix;

    @PostMapping("/upload")
    public Msg upload(@RequestParam("file") MultipartFile file) {
        // ① 判空
        if (file == null || file.isEmpty()) {
            return Msg.fail();
        }
        // ② 校验大小
        if (file.getSize() > MAX_SIZE) {
            return Msg.fail();
        }
        // ③ 取扩展名 + 白名单
        String original = file.getOriginalFilename();
        int dot = original == null ? -1 : original.lastIndexOf(".");
        if (dot < 0) {
            return Msg.fail();
        }
        String ext = original.substring(dot).toLowerCase();
        if (!ALLOWED_EXT.contains(ext)) {
            return Msg.fail();
        }
        // ④ UUID 重命名
        String newName = UUID.randomUUID().toString() + ext;
        File dest = new File(uploadDir + newName);
        // ⑤ 建目录
        if (!dest.getParentFile().exists()) {
            dest.getParentFile().mkdirs();
        }
        // ⑥ 落盘
        try {
            file.transferTo(dest);
        } catch (IOException e) {
            throw new RuntimeException("保存文件失败", e);
        }
        // ⑦ 返回 URL
        return Msg.success().add("url", urlPrefix + newName);
    }
}
```
> 想让失败时前端显示具体原因（而非通用提示），可以给 `Msg` 加一个 `public static Msg fail(String msg)` 重载，然后 `return Msg.fail("文件超过 5MB")`。

## 3. 接口契约（前端已按这个调）

| 项 | 约定 |
|---|---|
| 地址 | `POST /api/file/upload`（multipart/form-data） |
| 字段名 | `file` |
| 成功返回 | `Msg.success().add("url", "http://localhost:9991/upload/xxx.jpg")`，即 `{code:200, data:{url}}` |
| 失败返回 | `Msg.fail()`（code 400） |
| 关键 | `url` 必须是浏览器能直接打开的完整地址 |

## 6. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `@RequestParam MultipartFile` 拿到 null / 报错 | 没配 `multipartResolver` bean，或 id 不是 `multipartResolver` | springmvc.xml 加 ① 那个 bean，id 严格写 `multipartResolver` |
| 上传接口 404 / 前端连不上 | Controller 的 `@RequestMapping` 写成 `/upload` | 改成 `/api/file`（+`@PostMapping("/upload")`），见 2.1 |
| 上传接口和图片访问互相串 | Controller 占了 `/upload`，和静态映射 `/upload/**` 冲突 | 同上，Controller 走 `/api/file`，`/upload/**` 留给图片展示 |
| 图传上去了 `<img>` 404 | 没配 `<mvc:resources mapping="/upload/**">` | 配上（见 1.2 ③） |
| 超大文件丑陋报错 | 超过 web.xml `max-file-size`，容器直接拒 | 这就是硬底线；controller 里再做一次友好校验（见 2.2 ②） |
| 中文文件名乱码 / 重名覆盖 | 用了原文件名存盘 | UUID 重命名（见 2.2 ④） |
| IDEA 报 `Cannot resolve ${upload.dir}` | 静态检查不跑占位符替换 | 忽略，运行时正常 |

## 7. 安全清单（自查）
- [ ] 后端重新校验（不信前端）
- [ ] 类型校验用扩展名白名单；生产建议再加**魔数/magic bytes** 或 `ImageIO` 真实解码（扩展名可伪造）
- [ ] 大小上限（web.xml + controller 双重）
- [ ] **UUID 重命名**，拒绝用原文件名做存储路径（防路径穿越）
- [ ] 存在 webapp 之外的独立目录（重新部署不丢）
- [ ] 上传目录**禁止脚本执行**权限（防 webshell → RCE）
- [ ] 不向前端返回服务器内部绝对路径
- [ ] 上传接口要鉴权（别允许匿名传）

## 8. 生产演进：对象存储（OSS / MinIO / S3）
本地磁盘不能上生产：单点故障、不能水平扩容（多台机器文件不共享）、磁盘有限。
- **后端转发**：前端 → 后端 → OSS。简单，但后端吃带宽。
- **前端直传（企业主流）**：后端发 STS 临时凭证 / 预签名 URL，前端直传 OSS，后端不经手文件。
- 好消息：`img_path` 始终是 URL，从本地切 OSS **前端几乎不用改**。
